## 1. 3단이 받은 최신 화면 한 장을 4단이 또 받는다

- **무엇**: 3단(가장 최근 모습 보기)이 내려받은 앞페이지 한 장을, 4단(옛 화면 전수 정독)이
  다시 한 번 내려받는다. 도메인당 본문 요청 1회가 그냥 버려진다.
- **왜 지금 안 고쳤나**: 4단은 "대표 화면 고르기"를 자기 규칙으로 새로 하므로, 3단이 받은 장을
  물려주려면 두 단이 같은 장부를 공유해야 한다. 순서 재배치를 막 끝낸 참이라 같은 자리를 또
  건드리면 판정이 흔들린다.
- **되돌릴 조건**: 4단 대표 화면 선정이 한 달간 안 바뀌면, 받아 둔 본문을 넘겨주는 장부 하나를 둔다.
- **기한**: 2026-09-30
- **근거**: `tests/test_pipeline.py` 본문 요청 수 = 연도 수 + 3

## 2. 3단에서 찾은 위험 흔적이 스팸 확정이 아니면 버려진다

- **무엇**: `pipeline.py`의 `screen_recent` 가 최신 화면에서 계산한 규칙 검사 결과는, 그 자리에서
  탈락이 확정될 때만 결과에 남고 아니면 통째로 사라진다. 그 화면이 하위 주소였고 4단 대표에
  안 뽑히면 그 증거는 다시 볼 수 없다.
- **왜 지금 안 고쳤나**: 3단 결과와 4단 결과를 합치는 규칙(어느 쪽 판정을 이기게 할지)이 정해져
  있지 않다. 아무렇게나 합치면 같은 흔적이 두 번 세어져 감점이 겹친다.
- **되돌릴 조건**: 합치는 규칙을 정하면 3단 findings 를 4단 입력에 얹는다.
- **기한**: 2026-09-30

## 3. 본문이 많아 쪼개 읽을 때 구간별 "추천 주제"가 버려진다

- **무엇**: `analyze/ai.py` 의 부분 응답 병합 목록(`_PARTIAL_KEYS`)에 `recommended_topics` 가 없다.
  묶음별로 나온 추천 주제는 버려지고 마지막 통합 호출이 새로 짓는다.
- **왜 지금 안 고쳤나**: 그냥 합치면 비슷한 추천이 열 개씩 쌓인다. 중복을 걸러 3~5개로 줄이는
  규칙이 필요하다.
- **되돌릴 조건**: 추천 주제 중복 제거 규칙을 정하면 병합 목록에 넣는다.
- **기한**: 2026-09-30

## 4. 보고서 만들기가 화면에 연결되어 있지 않다

- **무엇**: 서버에 보고서 만들기(`POST /api/report`)와 완료·실패 알림이 다 있는데, 화면에 그것을
  누를 단추도 실패를 받아 보여 줄 자리도 없다. 주소를 직접 쳐야만 볼 수 있다.
- **왜 지금 안 고쳤나**: 단추를 어느 화면 어디에 둘지는 화면 설계 결정이라 코드 정리 범위 밖이다.
- **되돌릴 조건**: 운영자가 보고서 단추 자리를 정하면 배선한다.
- **기한**: 미정(운영자 결정 대기)
