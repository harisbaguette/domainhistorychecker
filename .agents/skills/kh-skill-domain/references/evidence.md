# 근거와 판정

## 수집과 해석을 분리하기

| 받은 자료 | 말할 수 있는 것 | 확정할 수 없는 것 |
|---|---|---|
| 권한 있는 RDAP 서버의 등록 레코드 | 등록 상태·공개된 이벤트 | 매물 여부·구매가·현재 운영자의 신원 |
| RDAP 404, DNS NXDOMAIN | 해당 조회에서 레코드 미발견 | 등록 가능·예약 아님·상표 안전 |
| 등록기관의 정확한 후보 검색 | 그 시점 판매처가 표시한 취득 방식·가격 | 예약 완료·결제 시점의 동일 가격 |
| 아카이브 스냅샷 본문 | 읽은 시점·주소의 실제 내용 | 미열람 기간·사이트 전체의 안전 |
| Wayback 빈 응답·접근 실패 | 그 요청으로 자료를 확보하지 못함 | 과거 사용 없음 |
| 위험 명단의 유효한 미등재 응답 | 해당 목록·대상·시점의 미등재 | 다른 명단·과거·Google 제재까지 안전 |
| 타임아웃·403·429·인증/리졸버 오류 | 조사 실패 또는 제한 | 위험 없음·위험 확정 |
| 상표 검색 결과 없음 | 관할·검색 조건 안에서 미발견 | 법적 사용 가능·권리 충돌 없음 |

## 별도 근거 파일

결론마다 다음을 연결한다. 키·연락처·계정 정보와 원문 전체를 불필요하게 저장하지 않는다.

- `target`: 정확한 도메인·URL 또는 브랜드 후보.
- `check`: 등록, 예약, 아카이브, 평판, 상표, 가격 등 확인 항목.
- `status`: `확인됨`, `미확인`, `미실시` 중 하나. 조회 성공과 안전을 같은 값으로 쓰지 않는다.
- `source`, `checkedAt`: 공식 URL, RFC 3339 시각과 시간대.
- `observed`: 응답 코드·표시 상태·가격 등 실제 관찰한 값. `null`은 0이나 무료가 아니다.
- `scope`: 대상 TLD·관할·쿼리·상품/서비스·크롤 묶음·열람 표본·등록 기간.
- `limitation`: 차단, 일부 수집, 비공개 자료, 일반 가격표 등 적용 한계.
- `judgment`, `nextAction`: 관찰에서 도출한 판단과 남은 확인.

가격은 `currency`, 최소 화폐 단위의 정수, 포함 기간, 세금·필수 수수료 조건을 함께 보관한다.
예를 들어 USD 11.08은 1108센트다. 일반 요금표와 개별 후보 견적에는 다른 범위를 붙인다.
오래된 근거는 현재 값으로 덮어쓰지 말고 새 확인을 구분한다. 구매 직전에는 취득 상태·가격을 다시 조회한다.

## 자료가 막혔을 때

공식 페이지가 동적이면 실제 브라우저 화면이나 문서화된 API를 사용한다. 홈페이지가 열린 것과 후보 검색 성공은 다르다.
접근 제한이 계속되면 관찰 가능한 다른 공식 자료로 확인 범위를 좁히고 남은 항목을 미확인으로 둔다.
유료·인증 자료가 없다는 이유로 가짜 값이나 평균값을 채우지 않는다. 핵심 취득·권리 조건이 미확인이면 조건부 검토로 남긴다.
