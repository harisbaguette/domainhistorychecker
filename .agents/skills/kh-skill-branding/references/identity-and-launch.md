# 표현과 출시

## 언어 체계

브랜드 약속을 소개 한 문장, 핵심 메시지, 이를 뒷받침하는 설명 순서로 쓴다.
슬로건은 기억과 역할이 분명해야 하며 사실 근거가 없는 1위·최고·유일 주장을 넣지 않는다.
상황에 따라 읽는 사람이 해야 할 일이 달라지므로 홈페이지 소개, 프로필, 가입 안내·오류·문의 응답의 예문을 함께 맞춘다.

말투는 ‘친근하다’ 같은 형용사만으로 끝내지 않는다. 호칭, 존댓말 수준, 문장 길이, 유머, 어려운 말, 느낌표의 사용을 실제 예문으로 보여 준다.
쓰면 좋은 표현과 피할 표현은 브랜드에 필요한 범위만 둔다. 기존 글의 말투를 보존해야 하면 실제 글을 읽고 특징을 추린다.
한국어 이름·영문 이름·제품명·도메인 표기를 일관되게 정한다.

## 시각 체계

고객이 느껴야 할 인상과 경쟁사와의 구별을 먼저 정한다. 특정 색이나 유행 스타일을 모든 업종에 그대로 적용하지 않는다.
방향을 비교할 때는 로고 형태, 서체 성격, 색 역할, 여백·사진·일러스트·모션의 차이를 실제 사용 장면에 연결한다.

제작 요청이면 설명으로 끝내지 않고 필요한 에셋을 만든다.
에셋은 `~/.codex/reference/asset-registry.md`의 ‘작업에서 고르는 법’과 `~/.codex/reference/asset-usage.md`를 읽고 실제 파일을 연결한다.
일본 제작자의 품질을 먼저 비교하되 브랜드 목적과 이용 조건을 우선한다. 설명용 그림은 사용자의 부드러운 스타일 선호를 반영한다.
래스터 생성·편집에는 사용 가능한 imagegen 도구를 사용한다. 도구가 없으면 제작 명세와 실제 에셋을 구별해 전달한다.
가져온 파일과 글꼴의 출처·라이선스는 `ASSETS.md`에 남기며, 기존 브랜드를 모방한 로고를 독창적인 결과라고 내놓지 않는다.

최종 브랜드 지침에는 필요한 항목을 포함한다.

- 로고의 기본·단색·반전 사용, 최소 크기와 여백, 작은 아이콘에서의 형태.
- 색의 역할과 HEX/RGB 값, 실제 배경에서의 글자 대비. 색만으로 상태를 표현하지 않는다.
- 한글·라틴 글꼴과 대체 글꼴, 제목·본문 역할과 상업 사용·임베딩 조건.
- 이미지·아이콘의 선택 기준과 모션의 강도, 모션 감소 환경의 정적 대안.
- 웹·프로필·공유 이미지 등 요청된 매체에서의 실제 적용 예시.

로고는 벡터 제작이 적합하면 SVG 원본과 필요한 PNG를 제공한다. 생성한 래스터를 이름만 SVG로 바꾸지 않는다.
투명 배경·작은 크기·밝고 어두운 배경에서 실제 렌더를 확인한다. 인쇄가 포함되면 인쇄소의 색·여백·출력 사양을 별도로 맞춘다.

웹 적용은 WCAG 2.2 AA의 일반 글자 4.5:1, 큰 글자 3:1 대비를 실제 전경·배경 조합으로 확인한다.
큰 글자는 약 24 CSS px 이상 또는 굵은 약 18.7 CSS px 이상 기준을 적용한다. 관련 UI 구성요소와 정보 전달 그래픽에는 비텍스트 대비 기준도 확인한다.
로고·브랜드명 글자에는 대비 예외가 있지만 같은 브랜드색을 쓴 본문·버튼까지 면제되지는 않는다. 이 일부 항목 통과만으로 WCAG 전체 준수를 선언하지 않는다.
OFL 글꼴로 만든 로고와 글꼴 파일 자체의 재배포·수정은 조건이 다르다. 폰트 파일을 배포하면 해당 라이선스·저작권 고지와 Reserved Font Name 조건을 확인한다. 모든 무료 글꼴을 OFL로 취급하지 않는다.

## 출시와 유지

도메인, 사이트 제목·설명, 공유 이미지, 소셜 프로필, 이메일 이름·서명을 같은 정체성으로 맞춘다.
리브랜딩은 옛 이름의 안내, 주소별 리디렉션, 이메일 연속성, 고객 공지와 되돌릴 순서를 준비한다.
웹 구현이 범위에 있으면 홈의 `WebSite` 구조화 데이터 `name`, `url`, 필요한 `alternateName`을 화면의 이름·제목과 일치시킨다. 검색 결과에 원하는 이름이 반드시 표시된다고 보장하지 않는다.
도메인까지 바꾸는 리브랜딩은 [보유 관리](../../kh-skill-domain/references/portfolio.md)의 주소·메일 이전 절차와 연결한다.
도메인 구매·입찰·유료 구독, 상표 출원·플랫폼 계정 생성, 외부 게시를 브랜딩 작업에 대한 자동 허가로 취급하지 않는다.

출시 점검에서는 고객이 무슨 서비스인지 설명할 수 있는지, 이름을 기억하고 입력할 수 있는지, 핵심 행동에 도달하는지 확인한다.
실제 관찰 자료가 없으면 검증 계획과 미확인 사항을 남긴다.
