# 브랜딩

고객이 누구를 위해 무엇을 하는 브랜드인지 이해하고 기억할 수 있도록 방향과 표현을 연결한다.
사용자가 이름만 요청하면 네이밍까지만, 전체 브랜딩을 요청하면 전략부터 실제 사용할 표현과 적용안까지 만든다.
도메인 구매·결제는 사용자가 직접 한다.

이 프로젝트 사용자의 기업명 선정은 [기업명 선정 기준](../../../branding/BRIEF.md)과 [후보 기록](../../../branding/candidates.json)을 먼저 읽고, 새 후보와 사용자 평가를 원장에 반영한다.

## 맥락부터 잡기

대화와 기존 자료에서 제품, 고객, 고객이 해결하려는 일, 경쟁 대안, 실제 강점, 판매 지역·언어, 가격대, 원하는 인상을 읽는다.
이미 정한 이름·가치·시각 요소는 이유 없이 바꾸지 않는다. 기존 고객이 있는 리브랜딩은 유지해야 할 인지 자산과 전환 부담도 본다.
핵심 사업이 미정이면 최소한의 질문을 묶어 하고, 가정으로 만든 시안은 가정임을 밝힌다. 고객 조사와 선호를 지어내지 않는다.

## 필요한 부분부터 수행

- 전략, 네이밍, 포트폴리오·리브랜딩: [전략과 이름](references/strategy-and-naming.md).
- 슬로건·말투·카피, 로고·색·타이포, 채널 적용: [표현과 출시](references/identity-and-launch.md).
- 이름의 도메인·상표 확인과 비용 비교: [도메인 스킬](../kh-skill-domain/SKILL.md)의 신규 도메인 절차를 적용한다.
- 상표·접근성·글꼴·검색 적용의 기준: [공식 자료](references/sources.md)의 필요한 조항을 확인한다.

브랜드 이름이 도메인 확보 때문에 뜻과 발음이 나빠지면 이름을 다시 고른다. TLD 변경·수식어 추가는 사용자가 허용한 범위에서만 비교한다.
이름만으로 차별화·매출·SEO 효과를 보장하지 않는다. 실제 고객 반응을 보지 않았다면 선호가 검증됐다고 쓰지 않는다.

## 전달할 결과

전체 브랜딩 요청이면 다음을 서로 일치하게 전달한다. 결과의 길이와 파일 수는 실제 활용에 맞춘다.

- **브랜드 핵심:** 고객, 해결하는 일, 차별점, 약속, 그 약속의 근거.
- **이름:** 추천안과 대안, 의미·발음·표기, 유사 이름과 도메인·상표의 확인 상태.
- **언어:** 소개 한 문장, 슬로건, 메시지 우선순위, 말투와 실제 채널별 예문.
- **시각:** 로고 방향, 색과 글꼴 역할, 이미지·모션 방향, 사용 예시. 제작까지 요청했으면 실제 파일과 렌더 결과.
- **적용:** 웹 첫 화면, 프로필·공유 이미지·이메일 등 요청한 채널에 바로 옮길 내용과 다음 행동.

독자가 쓸 문서에는 사용할 규칙·문구·값과 남은 결정을 적는다. 작업 이력·채점·출처는 별도 근거로 둔다.
사용자 지정 경로가 없고 파일 전달이 필요하면 `data/advisory/<브랜드명>/`에 둔다.
이름을 사용자가 확정하지 않았으면 모든 자료에 서로 다른 이름을 섞지 말고 한 추천안의 시안으로 일관되게 만든다.
