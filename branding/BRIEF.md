# 기업명 선정 기준

한국에서 여러 업종으로 확장할 기업의 그룹명을 고른다. 삼성·롯데처럼 독립된 이름으로 서고, 계열사에도 붙일 수 있어야 한다. 특정 업종은 정하지 않는다. 확정한 이름은 아직 없다.

## 이름을 먼저 고른다

- 롯데·엘지·두산 같은 국내 그룹명의 호칭을 기준으로 삼는다. 한국어 두 음절을 우선하고, 자연스러운 발음과 담백한 기업명 인상을 갖춘다. 외국어처럼 보이려고 만든 세 음절 조어는 피한다.
- 사용자는 텐브론을 명시적으로 거절했다. 영문 철자를 비틀어 만든 이름, 판타지·약품 같은 어감은 재추천하지 않는다. 엘지는 짧은 호칭의 참고 사례이며, 이미 등록된 영문 이니셜 도메인을 써도 된다는 뜻은 아니다.
- 설명 없이도 회사 간판과 명함에 쓰고 싶은 이름이어야 한다. 도메인이 비어 있다는 사실은 이름의 매력이 아니다.
- 단겸·시겸은 사용자 거절 후보다. 두 음절이라는 형식만 맞추거나, 사람 이름 같은 음절 조합에 ‘그룹’을 붙이는 작명을 반복하지 않는다.
- 큰봄도 사용자가 촌스럽다고 거절했다. 익숙한 우리말이나 밝고 정감 있는 뜻만으로 그룹명에 적합하다고 판단하지 않는다. ‘큰·봄’ 같은 감성적인 조합을 반복하지 않는다.
- 사용자는 큰봄을 고유명사로도 받아들이지 않았다. 일상어를 붙인 표현보다 독립된 기업 고유명사로 인식되는 이름을 원한다. 뜻풀이 없이도 소리와 이름 전체의 인상이 서야 한다.
- 사용자는 기업명에 쓰인 ‘겸’을 한국에서 익숙하게 받아들이기 어려운 어감으로 지적했다. ‘겸’으로 만든 후보는 제외한다. 한국에서 쓴다는 요구는 한국어 표기·글자 수에 그치지 않고, 한국 사람이 듣고 말할 때 자연스럽게 받아들이는 이름이어야 한다는 뜻이다.
- 사전에 있는 글자이거나 인명에 쓰인다는 사실을 상호의 자연스러움에 대한 근거로 삼지 않는다. 익숙한 발음과 기억하기 쉬운 이름 전체의 인상을 판단한다.
- 완성도가 부족한 후보를 ‘그중에서는 낫다’는 이유로 추천하지 않는다. 매력과 확보 조건을 함께 충족한 후보가 없으면 추천 후보 없음으로 남긴다.
- 짧고 또렷한 발음, 자연스러운 한국어 호칭, 쉬운 한글·영문 입력을 우선한다. 글자 수를 줄이려고 철자를 설명하기 어렵게 만들지 않는다.
- 한글 호칭을 먼저 만들고 영문 표기를 검토한다. 한글이 두 글자여도 영문이 길거나 외우기 어려우면 그 약점을 숨기지 않는다.
- `○○그룹`, `○○건설`, `○○유통`, `○○전자`로 읽어 기업명으로 어색하지 않은지 본다. 접미사를 붙일 수 있다는 이유만으로 좋은 이름이라고 평가하지 않는다.
- 임의의 음절을 이어 붙인 인상, 약·건강식품·유아 브랜드처럼 들리는 인상을 피한다. 뜻과 유래를 억지로 만들어 이름을 정당화하지 않는다.
- 새로운 후보는 이미 거절된 이름과 소리·구조·인상이 충분히 달라야 한다. 같은 이름의 첫 음절만 바꾸는 식으로 반복하지 않는다.
- 후보의 장점과 약점을 함께 판단한다. 사용자 취향이 확인되지 않은 이름을 확정안으로 기록하지 않는다.

## 확보 조건

- 이미 등록된 도메인의 매입·프리미엄 재판매는 제외한다. 접두사·하이픈·`group`을 붙여 조건을 우회하지 않는다.
- 같은 영문 이름의 `.com`, `.kr`, `.co.kr`을 모두 신규 등록할 수 있어야 한다.
- 주요 확장자도 함께 비어 있는 이름을 우선한다. 현재 비교 범위는 `.com`, `.kr`, `.co.kr`, `.net`, `.org`, `.co`, `.biz`, `.info`, `.io`, `.ai` 10종이다. 전 세계 모든 확장자를 확인했다고 표현하지 않는다.
- 기존 기업·브랜드·계정 사용 흔적이 적은 독자적인 이름을 선호한다. 등록 가능 여부, 현재 사용, 과거 이력, 상표 권리는 구분한다.
- RDAP 기록 미발견은 사전 선별에만 쓴다. 추천할 도메인은 판매처의 정확한 이름 검색으로 신규 등록 가능 표시를 확인한다.
- 도메인 확보가 모든 업종·국가의 이름 독점이나 분쟁 면제를 보장한다고 설명하지 않는다.
- 도메인 등록·구매·결제는 사용자가 직접 한다.

## 후보 관리

[후보 기록](candidates.json)이 누적 원장이다. 새 후보를 만들거나 조회하거나 사용자 평가를 받으면 같은 항목을 갱신한다. 사용자 거절, 추천 철회, 도메인 등록, 기존 사용, 보류, 조사 중, 사용자 검토 대기를 구분한다.

거절·철회된 이름은 사용자가 다시 지정하지 않는 한 재추천하지 않는다. 조회 근거는 `data/advisory/`의 원본 파일에 연결한다. 과거 조회 결과는 현재 등록 가능 여부로 재사용하지 않는다.
